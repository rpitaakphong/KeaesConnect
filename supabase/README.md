# Supabase Setup

Supabase provides staff authentication, staff permissions, assignment creation, student submissions, scoring storage, and admin result reporting for the Next.js app.

## Setup

1. Create or open the Supabase project.
2. Run `supabase/schema.sql` in the SQL editor.
3. Create staff users in Supabase Auth.
4. Insert matching staff rows:

```sql
insert into staff_users (id, email, display_name, role)
values ('AUTH_USER_UUID', 'staff@example.com', 'Staff Name', 'super_admin');
```

5. Deploy Edge Functions and set required secrets:

```sh
supabase functions deploy grade-english-literacy
supabase functions deploy manage-staff-user
supabase secrets set SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
```

After deploying `grade-english-literacy`, verify its supported-test contract from the Next.js app directory:

```sh
npm run smoke:english-grader
npm run smoke:english-grader -- --test-id spip-year-8-english-pre --nonblank
```

The default check uses blank responses and does not call OpenAI. The explicit `--nonblank` check makes one live grading request and should be used before activating a new AI-graded test.

6. Set these environment variables in `apps/workspace-next/.env.local` and Netlify:

```sh
NEXT_PUBLIC_SUPABASE_URL=YOUR_PROJECT_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

7. Open `/login`, sign in as a Super Admin, and manage staff access from `/admin/staff`.

## Active Routes

For KS2 Science registration, marking verification and activation, see [the KS2 live setup notes](../apps/workspace-next/docs/ks2-science-supabase.md). Use its targeted migration on an existing project; do not rerun the complete schema.

The Assessment Test uses `20261024090000_register_ks2_science_assessment_test.sql`. It registers 34 parts and 40 marks, initially inactive, and reuses the existing numeric-range grader. Regenerate and verify its keys from `apps/workspace-next` with `node scripts/ks2-assessment-supabase.mjs --migration` and `npm run verify:ks2-science`. The same script's `--audit` checks all 450 assessment scoring cases against stored keys; `--integration` verifies Ram and Ekamai assignment, submission and report flows while rolling back synthetic records. `--check` prevents migration/bootstrap drift during builds.

This targeted migration has been applied to KeaesWorkspaceProject and the assessment is active after verification. The staff catalog change in PR #10 must be merged before staff can generate assessment links from production. A labelled live QA submitted from the local review build scored 40/40; [its saved staff report](https://keaesconnect.netlify.app/admin/tests/results/ee6642be-3bb2-4212-b8ab-19a476ff25c7) contains all 34 answers. [Verification evidence](../apps/workspace-next/docs/ks2-science-evidence/assessment-verification.json) includes scoring, responsive layout, history and security checks. Preview deployments currently lack Supabase settings, so use their demo route for layout review. If subsequent live QA fails, deactivate only `ks2-science-assessment-test` while investigating; preserve saved results and review rules.

Student links must be generated by Test Admin and include an `assignment` query parameter. Direct test links without an assignment token are rejected.

Staff with `generate_links` permission must choose Ram or Ekamai for each generated assignment. Assignment links close after their first successful submission.

Seeded tests use Next routes such as `/tests/english-literacy-1/start`.
